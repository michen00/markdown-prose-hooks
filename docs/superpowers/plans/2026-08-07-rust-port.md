# Rust port implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a second implementation of the Markdown prose unwrap, in Rust, answering byte for byte to the same conformance corpus as the Python one, with ignore rules and a CLI conformance tier specified before either implements them.

**Architecture:** The corpus is the specification and both implementations are consumers of it. Two tiers: `corpus/cases/` pins the transform, `corpus/cli/` pins argument handling, file walking, exit codes and the ignore rules. The Rust crate is decomposed into eight small modules, each a set of `fn(&str) -> Option<_>` matchers testable alone, because the Python's single 829-line file suits Python and does not suit learning Rust. A differential fuzzer runs both binaries over generated documents and promotes every divergence into the corpus.

**Tech Stack:** Rust 1.86 with zero dependencies (std only), Python 3.10+ with zero runtime dependencies, `pre-commit`, `pytest`, `cargo test`, GitHub Actions.

**Source spec:** `docs/superpowers/specs/2026-08-06-rust-port-design.md`. Where this plan and the spec disagree, the spec wins and this plan is wrong.

## Global Constraints

Every task's requirements implicitly include this section.

- **Zero Rust dependencies.** std only. No `regex`, no `clap`, no `anyhow`, no `thiserror`. A crate with `regex = "1"` compiles ten crates in 6.6 s where an empty one compiles in 0.12 s, and `pre-commit` passes no `--locked`, so consumers do not even get pinned versions in exchange.
- **Zero Python runtime dependencies.** `dependencies = []` in `pyproject.toml` stays empty.
- **Rust MSRV is 1.86**, declared as `rust-version = "1.86"`. if-let chains stabilized in 1.88 and may not be used. `let ... else` (1.65) and `Option::is_some_and` (1.70) are available.
- **Python floor is `>=3.10`**, pegged to `pre-commit`'s own floor. Not a judgment call — `pre-commit` builds a `language: python` hook environment from its own interpreter.
- **Both manifests live at the repository root.** `pyproject.toml` and `Cargo.toml` side by side. `pre-commit` runs both installers with `cwd` at the repository root.
- **`Cargo.toml` holds a `[package]` block and nothing else** — no `[lib]`, no `[[bin]]`, no `[[test]]`, no `autotests`. This is why the binary lives at `src/bin/unwrap-markdown-prose-rs.rs` rather than `src/main.rs`: an autodiscovered `main.rs` takes the *package* name.
- **Parity boundary.** Exit codes and stdout match byte for byte. stderr need only match in meaning.
- **Parity means matching Python, not matching CommonMark.** The code-span approximation is reproduced, not corrected. Correcting it is an explicit non-goal of this plan.
- **Every commit is signed.** Never pass `--no-gpg-sign` or disable `commit.gpgsign`. A commit that will not sign is a signing problem to solve.
- **Commit messages** follow Conventional Commits; `.gitlint` is the authority (title 5–50 characters, body wrapped at 72).
- **One commit per task.** From Task 6 onward the corpus is the gate.

### Five Unicode facts that decide most of the port

Each was established by enumerating all 0x110000 code points in both languages. Getting any of them wrong produces a port that passes the corpus and diverges in the field.

| fact | consequence |
| -- | -- |
| Python `\s` and `str.strip()` select 29 code points: Unicode `White_Space` **plus** `U+001C`–`U+001F` | `str::trim` is **not** `str.strip()`. Every port of `.strip()` uses a local `py_trim`. |
| Python `\d` on a `str` pattern is Unicode category `Nd` — and not one set: 650 code points on 3.10, 680 on 3.13 | Narrowed to `[0-9]` by Task 6, because the Python did not agree with itself across its own supported interpreters and CommonMark restricts ordered list markers to ASCII. `is_ascii_digit` is now correct; `char::is_numeric` (`Nd \| Nl \| No`, 1911 points) still is not. **`argparse` is the exception** — its `_negative_number_matcher` is CPython's own `\d` and is not ours to narrow. See Task 11. |
| Python `[A-Z]` in a `str` pattern is the literal range `U+0041..U+005A` | `char::is_uppercase` is wrong; `is_ascii_uppercase` is right. |
| `str.splitlines()` breaks on ten boundaries | Narrowed to `\n`, `\r\n`, `\r` by Task 3. Until that lands, do not assume `split_inclusive('\n')` equals it. |
| CPython `sys.stdout` is a `TextIOWrapper` with `newline=None` | On Windows every `\n` written reaches a pipe as `\r\n`. Byte-for-byte stdout parity requires the CLI harness to compare against the platform's translation, or both implementations to write bytes. See Task 2 Step 4. |

- [x] **Step 1: Write the tier's format document**

Create `corpus/cli/README.md`:

````markdown
# CLI conformance tier

The transform tier next door specifies what the unwrap does to a document. This tier specifies everything a document cannot describe: which files the tool opens, what it writes, what it prints, and what it exits with. Every implementation runs this directory through its own binary.

## Layout

```text
corpus/cli/<slug>/
  case.txt      metadata and rationale
  tree/         the input file tree, copied to a scratch directory before the run
  expected/     the tree exactly as it must look afterward
  stdout.txt    expected stdout, verbatim; absent means empty
```

## `case.txt`

Plain `key: value` lines. Four keys, all required:

| key | meaning |
| -- | -- |
| `name` | What invariant the case pins, as a sentence |
| `why` | The reasoning. Surfaces in the failure message |
| `argv` | Arguments after the program name, split on whitespace |
| `exit_code` | The expected process exit status |

`argv` has no quoting rules. A case needing a path with a space in it is a reason to extend the format deliberately, not to smuggle in a shell.

## The rules that make it unambiguous

**`expected/` is the whole tree, not a diff.** Every file that must exist after the run appears in it, including files the run did not touch. A file present in `tree/` and absent from `expected/` must have been deleted. This is more typing than absent-means-unchanged and it is the only version that can express a deletion.

**Empty directories cannot be expressed.** Git does not store them. A case needing one is a reason to extend the format.

**The run's working directory is the copied tree**, so `argv` holds relative paths and needs no substitution.

**stdout is compared byte for byte. stderr is not compared at all.** Byte-identical error prose across two languages is maintenance cost with no user-visible payoff. Exit codes and stdout are the contract.

**Line endings are bytes.** `.gitattributes` marks `corpus/cli/**` as `-text -diff` for the same reason it marks the transform tier: a case pinning CRLF stops pinning anything the moment git normalizes it on checkout.

## Adding a case

Write the files and it is picked up automatically. Prefer a case that pins one decision, and put the argument in `why` — the slug becomes the test id, and the `why` is what the next person gets when they are staring at a failure.
````

```python
"""Run the CLI conformance tier against every built implementation.

The transform tier (`corpus/cases/`) specifies what the unwrap does to a
document. This tier specifies what the *program* does: which files it opens,
what it writes, what it prints, and what it exits with. The format is
documented in `corpus/cli/README.md`.

Parameterization is over (case, runner) rather than case alone, so adding the
Rust binary is a one-entry change to `_runners()` and not a change to any test.
"""

import shutil
import subprocess
import sys
from dataclasses import dataclass
from pathlib import Path

import pytest

_CLI_CORPUS = Path(__file__).resolve().parents[1] / "corpus" / "cli"
_REPO = Path(__file__).resolve().parents[1]


@dataclass(frozen=True)
class Runner:
    """One implementation under test, named and invocable."""

    label: str
    argv: tuple[str, ...]

    def __str__(self) -> str:
        """Return the label, used as the parametrize id."""
        return self.label


def _runners() -> list[Runner]:
    """Return every implementation that is currently built.

    Task 12 adds the Rust binary here. Nothing else in this file changes.
    """
    return [Runner("py", (sys.executable, "-m", "markdown_prose_hooks.unwrap"))]


class CliCase:
    """One CLI case: its tree, its expectations, and why it exists."""

    def __init__(self, directory: Path) -> None:
        """Load the case rooted at ``directory``."""
        self.slug = directory.name
        self.directory = directory
        meta = _parse_meta(directory / "case.txt")
        self.name = meta["name"]
        self.why = meta["why"]
        self.argv = meta["argv"].split()
        self.exit_code = int(meta["exit_code"])
        stdout = directory / "stdout.txt"
        self.stdout = _read_bytes(stdout) if stdout.exists() else b""

    def __str__(self) -> str:
        """Return the slug, used as the parametrize id."""
        return self.slug


def _read_bytes(path: Path) -> bytes:
    """Return ``path`` as bytes, with no newline translation whatsoever."""
    return path.read_bytes()


def _parse_meta(path: Path) -> dict[str, str]:
    """Return the ``key: value`` pairs in a case's metadata file."""
    meta: dict[str, str] = {}
    for line in path.read_text(encoding="utf-8", newline="").splitlines():
        if not (stripped := line.strip()):
            continue
        key, _, value = stripped.partition(":")
        meta[key.strip()] = value.strip()
    return meta


def _snapshot(root: Path) -> dict[str, bytes]:
    """Return every file under ``root`` as posix-relative path to bytes."""
    return {
        path.relative_to(root).as_posix(): path.read_bytes()
        for path in sorted(root.rglob("*"))
        if path.is_file()
    }


def load_cli_corpus() -> list[CliCase]:
    """Return every CLI case, ordered by slug."""
    if not _CLI_CORPUS.is_dir():
        return []
    return [CliCase(d) for d in sorted(_CLI_CORPUS.iterdir()) if d.is_dir()]


CLI_CASES = load_cli_corpus()


def test_the_cli_corpus_is_not_empty() -> None:
    """A wrong corpus path would otherwise make every case silently vanish."""
    assert CLI_CASES, f"no CLI cases found under {_CLI_CORPUS}"


@pytest.mark.parametrize("runner", _runners(), ids=str)
@pytest.mark.parametrize("case", CLI_CASES, ids=str)
def test_cli_case(case: CliCase, runner: Runner, tmp_path: Path) -> None:
    """Each case's run produces its expected tree, stdout and exit code."""
    scratch = tmp_path / "tree"
    shutil.copytree(case.directory / "tree", scratch)

    completed = subprocess.run(  # noqa: S603
        [*runner.argv, *case.argv],
        cwd=scratch,
        capture_output=True,
        check=False,
    )

    context = f"{case.name} — {case.why}"
    assert completed.returncode == case.exit_code, (
        f"{context}\nstderr: {completed.stderr.decode('utf-8', 'replace')}"
    )
    assert completed.stdout == case.stdout, context
    assert _snapshot(scratch) == _snapshot(case.directory / "expected"), context
```

```python
    Not ``str.splitlines``, which recognizes ten boundaries. The extra seven
    — ``\v``, ``\f``, ``U+001C``-``U+001E``, ``U+0085``, ``U+2028``,
    ``U+2029`` — are a bug rather than a feature here: a paragraph containing
    one is treated as two soft-wrapped lines and joined, and because the join
    calls ``strip()`` the separator is deleted outright. Losing a character is
    worse than declining to unwrap, and no Markdown renderer reads any of the
    seven as a break. The narrow set is also stable across interpreters, where
    ``splitlines``' is a property of the runtime rather than of this tool.
    """
    lines: list[str] = []
    append = lines.append
    start = index = 0
    length = len(text)
    while index < length:
        char = text[index]
        if char == "\r":
            end = index + 2 if text[index + 1 : index + 2] == "\n" else index + 1
        elif char == "\n":
            end = index + 1
        else:
            index += 1
            continue
        append(text[start:end] if keepends else text[start:index])
        index = start = end
    if start < length:
        append(text[start:])
    return lines
```

### The resolved semantics

The spec's prose leaves twelve questions open. Each is answered here, once, so two hand-written implementations cannot drift. **These answers are the specification** — where a case and this table disagree, the case is right and this table is a typo.

| question | answer |
| -- | -- |
| What is matched? | The candidate string **as given** — the argv element, the `--files-from` line, or the discovery result — split on `/` into components, with `.` components dropped and `..` resolved by popping. Never routed through `pathlib.Path` or `std::path::Path` first, because `Path("a/../b.md").as_posix()` keeps the `..` and the normalizer does not. |
| Absolute candidates? | Relativized against the anchor root by textual prefix match. If the candidate does not lie under the root, it is matched by its components as-is. Symlinks are **not** resolved — this is lexical. |
| Anchor root? | The process working directory, for patterns from both sources. `--ignore-file` pointing elsewhere does **not** move the root; the root is where the tool is running, which is what makes `pre-commit`'s relative paths work. |
| Windows separators? | Candidate `\` becomes `/`, on Windows only. Pattern `\` is literal everywhere. A drive prefix is stripped from candidate **and** root by one shared function, so the two provably meet. |
| Does a slash imply anchoring? | **No.** The spec says a leading `/` anchors and without it a pattern matches at any depth, and that is taken literally, *diverging from gitignore deliberately*. `docs/x.md` matches at any depth; `/docs/x.md` matches only at the root. One rule beats gitignore's two, and the subset exists to be small. |
| Trailing `/`? | Restricts to directories, and since the tool is given files, `build/` excludes `build/x.md` — it matches when a **proper prefix** of the candidate's components matches, rather than the whole. |
| Does `*` match a leading dot? | Yes. There is no hidden-file special case. |
| Can `*` match empty? | Yes. `*x.md` matches `x.md`. |
| `**` positions | `**/b` is any depth then `b`; `a/**` is `a` then anything below, at least one component; `a/**/b` is `a`, any number of components including zero, then `b`. A bare `**` matches everything. Three or more stars in a segment collapse to `**` if the segment is *only* stars, and otherwise to a single `*`. |
| Ordering | `.unwrapignore` patterns first, in file order, then `--exclude` globs in argument order. Last match wins across the combined list, so an `--exclude` can override the file and a `!` in the file cannot override a later `--exclude`. |
| Missing files | A missing default `.unwrapignore` is silent. A missing `--ignore-file` is an **error** — it was asked for by name. |
| Case sensitivity | Sensitive, on every platform. |
| Trailing whitespace in a pattern | Stripped, unless the final space is escaped with a backslash. A pattern that is only `/` is ignored. `\#` and `\!` escape a leading `#` and `!`. |
| Does exclusion apply to the `--files-from` file itself? | No. It filters the paths *inside* it. |

- [x] **Step 4: Implement the matcher**

Add to `unwrap.py`. The single most important detail is the branch order inside the segment matcher: **the `*` branch must be tested before the literal branch**, or a candidate containing a literal `*` consumes the wildcard as a literal and loses its backtrack point.

```python
def _match_glob_segment(pattern: str, text: str) -> bool:
    """Return ``True`` when one path component matches one glob segment."""
    # The classic single-saved-star backtracking walk. The wildcard branch is
    # tested FIRST, and that order is load-bearing rather than stylistic: with
    # the literal branch first, a text character that happens to be `*` matches
    # the pattern's `*` as a literal, no backtrack point is recorded, and
    # `*x.md` stops matching a file genuinely named `*ax.md`. A star is a legal
    # filename character on every platform this runs on.
    star_pattern: int | None = None
    star_text = 0
    p = t = 0
    while t < len(text):
        if p < len(pattern) and pattern[p] == "*":
            star_pattern = p
            star_text = t
            p += 1
        elif p < len(pattern) and pattern[p] in ("?", text[t]):
            p += 1
            t += 1
        elif star_pattern is not None:
            star_text += 1
            t = star_text
            p = star_pattern + 1
        else:
            return False
    while p < len(pattern) and pattern[p] == "*":
        p += 1
    return p == len(pattern)
```

```rust
//! Run the language-neutral conformance corpus against the Rust implementation.
//!
//! The same directory `tests/test_corpus.py` runs. These tests hold no
//! expectations of their own: each case carries its input, its expected output,
//! and the reasoning for both. The format is documented in `corpus/README.md`.
//!
//! Each test collects every failure and reports them together, because the
//! useful signal from a conformance suite is how many cases a change broke.

use std::collections::BTreeMap;
use std::fs;
use std::path::{Path, PathBuf};

struct Case {
    slug: String,
    name: String,
    why: String,
    paragraphs_unwrapped: usize,
    line_breaks_removed: usize,
    input: String,
    expected: String,
}

fn corpus_root() -> PathBuf {
    Path::new(env!("CARGO_MANIFEST_DIR")).join("corpus").join("cases")
}

/// Read a file with no newline translation.
///
/// `fs::read_to_string` performs none — unlike Python's default text mode,
/// which rewrites CRLF to LF and would turn a real regression into a pass.
fn read_verbatim(path: &Path) -> String {
    fs::read_to_string(path).unwrap_or_else(|err| panic!("{}: {err}", path.display()))
}

fn parse_meta(text: &str) -> BTreeMap<String, String> {
    let mut meta = BTreeMap::new();
    for line in text.lines() {
        let trimmed = line.trim();
        if trimmed.is_empty() {
            continue;
        }
        if let Some((key, value)) = trimmed.split_once(':') {
            meta.insert(key.trim().to_owned(), value.trim().to_owned());
        }
    }
    meta
}

fn load_corpus() -> Vec<Case> {
    let mut directories: Vec<PathBuf> = fs::read_dir(corpus_root())
        .expect("corpus directory is readable")
        .filter_map(|entry| entry.ok().map(|e| e.path()))
        .filter(|path| path.is_dir())
        .collect();
    directories.sort();
    directories
        .into_iter()
        .map(|directory| {
            let meta = parse_meta(&read_verbatim(&directory.join("case.txt")));
            let get = |key: &str| {
                meta.get(key)
                    .unwrap_or_else(|| panic!("{}: missing key {key}", directory.display()))
                    .clone()
            };
            Case {
                slug: directory.file_name().unwrap().to_string_lossy().into_owned(),
                name: get("name"),
                why: get("why"),
                paragraphs_unwrapped: get("paragraphs_unwrapped").parse().unwrap(),
                line_breaks_removed: get("line_breaks_removed").parse().unwrap(),
                input: read_verbatim(&directory.join("input.md")),
                expected: read_verbatim(&directory.join("expected.md")),
            }
        })
        .collect()
}

fn report(kind: &str, total: usize, failures: &[String]) {
    assert!(
        failures.is_empty(),
        "{} of {total} cases failed {kind}:\n\n{}",
        failures.len(),
        failures.join("\n\n"),
    );
}

#[test]
fn the_corpus_is_not_empty() {
```

5. **The failure restart is `i + 1`, inside the run, not `i + run`.** They happen to be equivalent here, and the equivalence depends on the k=1 case rather than on anything structural.

```rust
/// Find the next span at or after `from`, or `None` if there is none.
fn next_span(bytes: &[u8], from: usize) -> Option<(usize, usize)> {
    let mut i = from;
    while i < bytes.len() {
        if bytes[i] != TICK {
            i += 1;
            continue;
        }
        // `(`+)` is greedy, so the engine tries the whole run first and
        // backtracks one backtick at a time; the first opener length that
        // finds a closer wins. Ascending order gives different answers.
        let mut run = 0;
        while i + run < bytes.len() && bytes[i + run] == TICK {
            run += 1;
        }
        for k in (1..=run).rev() {
            if let Some(end) = find_closer(bytes, i + k, k) {
                return Some((i, end));
            }
        }
        i += 1;
    }
    None
}

/// The whole of `(?:(?!\1).)*\1`.
///
/// The body loop consumes one character at a time and refuses to start one
/// where `\1` matches, so it halts at the first position carrying `k`
/// backticks — where the closer then matches — or at a `\n` or end of input,
/// where it cannot. Every position it did consume failed the same test the
/// closer would apply, so backtracking the body can never rescue the attempt
/// and a linear scan is exact.
fn find_closer(bytes: &[u8], start: usize, k: usize) -> Option<usize> {
    let mut j = start;
    loop {
        if j + k <= bytes.len() && bytes[j..j + k].iter().all(|&b| b == TICK) {
            return Some(j + k);
        }
        // `.` does not match `\n` without re.DOTALL, and matches every other
        // character including `\r`, `\x0b`, `\x0c`, U+0085, U+2028, U+2029.
        if j >= bytes.len() || bytes[j] == LF {
            return None;
        }
        j += 1;
    }
}
```

Byte indexing is safe here: every position tested is a backtick or a newline, both ASCII, and the returned offsets land on backticks and are therefore character boundaries.

### The four hazards

1. **`[A-Z]` in a Python `str` pattern is the literal range `U+0041..U+005A`.** Not a Unicode property — `re.UNICODE` does not change character-class ranges. Use `is_ascii_uppercase`; `char::is_uppercase` would accept `É` and `Ω` where Python does not.

3. **Three of the four label patterns reject leading whitespace; `_MATCH_WHOLE_LINE_BOLD` accepts it.** `is_label_line` lstrips first, which papers over the difference at that call site and not at any other.
4. **`_MATCH_SPEAKER_PREFIX`'s `{0,3}` counts group repetitions, not characters** — at most four space-separated words. No character counting is needed anywhere in these two modules.

### The design

Python holds mutable state in closure variables that `flush()` mutates from inside the loop. Rust cannot express that shape. Use a struct with methods:

```rust
struct Paragraph<'a> {
    kind: Kind,               // Top | Blockquote | ListItem
    first_line: &'a str,
    first_prefix: &'a str,
    first_content: &'a str,
    last_eol: &'a str,
    content_col: usize,       // CHARACTERS, never bytes
    extras: Vec<(&'a str, &'a str)>,  // (raw_line, post_prefix_content)
}

struct Unwrapper<'a> {
    output: String,
    paragraph: Option<Paragraph<'a>>,
    paragraphs_unwrapped: usize,
    line_breaks_removed: usize,
    in_front_matter: bool,
    fence: Option<(char, usize)>,
    html_literal_terminator: Option<&'static str>,
    html_block_tag: Option<String>,
    bq_fence: Option<(char, usize)>,
    bq_html_literal_terminator: Option<&'static str>,
    bq_html_block_tag: Option<String>,
}
```

`Option<(char, usize)>` collapses Python's `in_fence` / `fence_char` / `fence_len` triple into one value that cannot be half-set. Output is an owned `String` rather than a `Vec<&str>`: the label-row branch builds joined lines that borrow from nowhere, so a borrowed output would need an owning enum for no gain.

### Branch order is the specification

The main loop's fourteen branches run in this order and **the order is load-bearing**. Getting it wrong is the most likely port bug, and several orderings look arbitrary and are not.

| # | condition | effect |
| -- | -- | -- |
| 1 | `index == 0 && in_front_matter` | flush, emit, continue |
| 2 | `in_front_matter` | flush, emit; clear on `---` or `...`; continue |
| 3 | `html_literal_terminator` armed | flush, emit; clear when the terminator appears; continue |
| 4 | `html_block_tag` armed | flush, emit; clear on `</tag>` **or a blank line for a non-raw tag**; continue |
| 5 | `fence` armed | flush, emit; clear on a closing fence; continue |
| 6 | any `bq_*` armed | if the line carries a blockquote marker: emit, update, continue. **Otherwise clear all five and fall through** — the only branch that does not `continue` |
| 7 | body is blank | flush, emit, continue |
| 8 | `index` is inside a link-block run | flush, emit, continue |
| 9 | opening fence | flush, arm, emit, continue |
| 10 | hard break or whole-line bold | flush, `emit_pass_through`, continue |
| 11 | blockquote | structural break → flush, emit, arm container state; else append to a `Blockquote` paragraph **unless a speaker prefix starts a new one** |
| 12 | list marker | **flush unconditionally**, then structural break → emit; else open a `ListItem` paragraph |
| 13 | prose line | new paragraph if none open or a speaker prefix; else append |
| 14 | fallthrough | list-item continuation if indented past `content_col`; else flush and `emit_pass_through` |

Two orderings that look wrong and are right: **branch 4 precedes branch 7**, which is what lets a blank line close a non-raw HTML block — reorder them and `<div>` blocks never close. **Branch 12 flushes unconditionally where branch 11 does not**; symmetrizing them changes behavior.

- [x] **Step 2: Write `flush` and `flush_label_rows`**

- no extras → emit `first_line`, no counts change

```rust
pub struct Rng { state: u64 }

impl Rng {

        // 0 is a fixed point of xorshift; map it to something else.
        Self { state: if seed == 0 { 0x9E3779B97F4A7C15 } else { seed } }
    }
    pub fn next_u64(&mut self) -> u64 {
        let mut x = self.state;
        x ^= x << 13;
        x ^= x >> 7;
        x ^= x << 17;
        self.state = x;
        x

}
```

- **speaker headings at the exact `{0,39}` boundary**: `"A" + "e"*39 + ":"` matches and `"A" + "e"*40 + ":"` does not — verify both before committing them
- **timestamped headings with non-ASCII digits**, which is the one Unicode-aware counted quantifier in the codebase
- the four C0 separators `U+001C`–`U+001F` inside prose, which `str.strip` eats and `str::trim` does not
- mixed line endings within one document

Assert the bank's own properties in a test: that the boundary pair really straddles the boundary, and that at least one fragment contains a non-ASCII digit. A bank that cannot reach a hazard is worse than no bank, because it reports coverage it does not have.

- [x] **Step 3: Write the runner**

- [x] **Step 4: Write the minimizer**

Delta-debugging by line removal: repeatedly try deleting each line and keep any deletion that preserves the divergence, until a pass changes nothing. A hundred-line divergence is not a bug report; a three-line one is.
