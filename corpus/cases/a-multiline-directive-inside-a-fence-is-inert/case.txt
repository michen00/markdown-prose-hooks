name: A multi-line directive inside a fenced code block is not a directive
why: Fenced content is quoted text, and a document teaching a reader to write the multi-line form prints it. At the top level the fence guard runs before any marker is looked for, so this much holds without a rule of its own -- but only while the comment run is accumulated below that guard, and an implementation that started accumulating on the raw line would break it. Guard order gives nothing for free where nothing armed the guard, which is the half this case does not reach: a fence inside a quote has to be recognized with the whole blockquote stack off before the ordering applies at all, and `a-multiline-directive-inside-a-twice-quoted-fence-is-inert` is where that is pinned.
